# VERDICT: NEEDS-EDITS

Structurally strong — the ownership change in §4.1, `.PART`+readback, `RUNID`, and "DISAGREE is a deliverable" are right. Six things a builder would guess at or get burned by.

## 1. Where a builder is blocked or guesses

- **`EVAL` is underspecified and it is the join column.** No corpus container (magic? endianness? id validation?), no context window/stride for the perplexity slice, and — worst — no definition of how an f32 logprob becomes `nll_q16`: log base, rounding, accumulation order. An integer *representation* of a nondeterministic float reduction is not bit-comparable; you inherit the ternary-drift problem, not escape it. Two builders ship two incomparable numbers and the whole cross-box claim evaporates. **Top blocker.**
- **`merge_key` "step inputs" undefined** — literal directive line, file sha, or name? Needs a byte-exact serialization or the join breaks silently between phases.
- **`NAME_MAX_BYTES = 32` is off by one.** `write_named` (`job.rs:693`, not 654) uses `[u16; 32]` and `CStr16::from_str_with_buf` needs room for NUL → 31 max. A 32-byte name returns `Err`, not `ERR bad-name`.
- **`<NAME>.PART` is not 8.3** (`MODEL.SAF.PART`, two dots), while §9 reserves >8.3 names to Debian. Use one fixed staging name (`STAGE.PRT`).
- Cited LOC/line numbers are stale (`job.rs` 1396, `server.rs` 757, `net/mod.rs` 1475; `RECV_MAX_BYTES` is :125).

## 2. Protocol ambiguities

- **`END\n` mismatch has no slug.** Add `bad-frame`, and say whether rejection precedes or follows readback.
- **`GET` cannot honour "no partial success"** — the header is already committed. Mandate: mid-stream read failure ⇒ **close the connection**, never a truncated frame.
- **`PUT` abort path unstated**: after `XFER_STALL_MS`, does the server `ERR`, close, delete `.PART`, and is it then `BUSY`?
- **`REPLAY` sequencing**: must the client still send `JOB…END` for the server to drain? Both readings are in the text.
- **The `RUNID` ring is RAM** — a watchdog reset makes a re-issued id `NEW` and double-spends. Say so. Also no `RECORD_MAX`: 8 × (unbounded `job.N.detail`) in heap.
- **`AUTH` leaves `GET` open** — a `TOKEN`ed box still serves `MODEL.SAF` to the LAN.
- **`LS`**: is `END` counted in `<n>`, and does >256 truncate or error?

## 3. Iron hazards QEMU hides

- **`TCP_RX_BYTES`/`TX` are 4096.** A 4 KiB window over real Ethernet makes a 1.83 GB `PUT` RTT-bound; hostfwd hides it completely and `files-test` moves 256 KiB. Either raise the buffers or cap `PUT_MAX` to what fits a budget.
- **Watchdog re-arm covers the transfer, not the readback.** A 1.8 GB sha256 readback off USB2 under `FILES_WD_S=300` with no re-arm resets the box — and that reset spends `BootNext`.
- **Pointer-swap needs double capacity**: `MODEL.SAF` + `MODEL.NEW` = 3.7 GB. The "free clusters − 16 MiB" rule doesn't say this.
- `FileSystemInfo` free-space is advisory on vendor FAT drivers; `no-space` may arrive as `io`.

## 4. Rule A

Clean on `tps`. Two leaks: `merge_key` excludes `env`, and `AGREE` requires only differing `cpuid_sig` — so a TCG guest can be a replication partner in a published table. `MEMBW` is ungated and bandwidth-shaped. §11's specimen digests/`nll_q16` will be quoted as measured.

## 5. Is POOL useful for the own-model directive?

**Plainly: no — it is an eval/determinism harness.** Cross-ISA agreement, receipt verification, perplexity sharding: real. Training: the ES path in §9 is honestly labeled, but pushing 1.83 GB per generation through a 4 KiB window dominates any compute win. Do not let POOL be described as progress on training.

## The 5 changes

1. Fully specify `EVAL` + the `nll_q16` reduction (and `merge_key` input serialization).
2. Name layer: 31-byte cap, fixed 8.3 staging name, double-capacity rule for artifact swap.
3. Transport realism: bigger socket buffers, readback watchdog re-arm, a ≥64 MiB case in `files-test`.
4. Complete the abort/error table: `bad-frame`, GET-closes, PUT-abort, REPLAY drain, ring volatility, `RECORD_MAX`.
5. `env=iron` guard on `AGREE`/`pool_digest`; gate `GET` behind `AUTH`; stamp §11 SPECIMEN.
